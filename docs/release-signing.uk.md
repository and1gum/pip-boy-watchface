# Підпис release і перенесення конфігурації

[English](release-signing.md) · [Установлення](install.uk.md)

Release 0.3.0 використовує окремий RSA-4096 ключ на 30 років та криптографічно підтверджений перехід від початкового debug-сертифіката проєкту. На Android 15+ це дозволяє оновити застосунок через `install -r` з новим ключем. Поточний підпис APK — **Pip-Boy Release**, а не Android Debug. Механізм описано в документації [APK Signature Scheme v3](https://source.android.com/docs/security/features/apksigning/v3) та [apksigner](https://developer.android.com/tools/apksigner).

Відбитки сертифікатів SHA-256 є публічними:

| Сертифікат | SHA-256 |
| --- | --- |
| Початковий debug проєкту | `4d4d850ac4b7bd2cda61b2d269e4a6bace213e23866621e105b5c65624635601` |
| Release проєкту | `94f7ecd7517e92587828869c09d03d621561ec277c53c7e5e5fd76871f24da91` |

Обидва APK використовують однаковий signing lineage. Він дозволяє передати наявні дані новому підпису та забороняє повернення до старого debug-підпису. Ідентифікатори пакетів, параметри WFF (`hr2`–`hr5`), ідентифікатори й порядок слотів та назви компонентів провайдерів збережені. Перехід утримує наявну інсталяцію з її даними; він не експортує й не відтворює приватну конфігурацію системного циферблата.

## Для автора випусків: одноразове налаштування

Для наступних офіційних збірок використовуй **наявний** каталог підпису проєкту. Не генеруй новий ключ для кожного випуску. Типовий каталог — `~/.local/share/pip-boy-signing/`; пароль читається з приватного файла `password` і не передається відкритим текстом у командному рядку. Для відновленого каталогу в іншому місці задай `PIPBOY_SIGNING_DIR`. Не додавай ключ, пароль або приватні резервні копії до Git чи файлів випуску.

Для нового незалежного розповсюдження налаштування запускається явно й відмовляється перезаписувати наявні ключі:

```bash
bash scripts/init-release-key.sh \
  --old-key "$HOME/.android/debug.keystore" \
  --reference-apk artifacts/PipBoy-0.2.0-debug.apk \
  --reference-apk artifacts/PipBoy-Compass-0.2.0-debug.apk \
  --backup-dir /absolute/path/outside/repository/pip-boy-signing-backup
bash scripts/build-release.sh
```

Скрипт перевіряє відповідність старого ключа обом APK, створює постійний ключ і підтвердження ротації, потім побайтово перевіряє окрему резервну копію. Інший локальний debug-ключ не дозволить оновити debug APK проєкту. Новий незалежний release-ключ також не оновить офіційний release. Для таких інсталяцій завантажуй офіційні APK.

Для відновлення підпису поверни **всі файли** з приватної резервної копії в приватний каталог, задай для нього `PIPBOY_SIGNING_DIR` і запусти release-збірку. Публічний сертифікат або старий APK не замінюють втрачений приватний ключ. Початковий debug.keystore також збережи окремо.

## Збереження конфігурації годинника

Використовуй встановлювач із перевірками:

```bash
bash scripts/install-release.sh --serial WATCH_IP:CONNECT_PORT
```

Він завантажує встановлені APK, порівнює коди версій і бібліотекою Android `apksig` перевіряє справжній signing lineage та дозвіл на передачу даних для версії Android годинника. Обидва пакети мають пройти перевірку до встановлення першого. Сторонній підпис або нижча версія зупиняють процес. Запасного кроку з видаленням або очищенням даних немає.

Перед установленням скрипт зберігає попередні APK, доступні архіви налаштувань debug, дампи дозволів, wallpaper та знімок екрана в `~/.local/state/pip-boy/backups/`. Це контрольний знімок. Wear OS зберігає налаштування циферблата та прив'язки ускладнень поза даними цих двох пакетів; дампи не дозволяють автоматично відновити їх після видалення чи скидання. Приватні знімки можуть містити розташування та історію; зберігай їх приватно.

Налаштування зберігає саме прямий перехід підпису. Якщо годинник його відхиляє, залиш debug-інсталяцію на місці й досліди помилку. Не видаляй її з розрахунком на повне відновлення зі знімка. 23 жовтня 2026 року обидва опубліковані APK 0.3.0 встановлено поверх debug 0.2.0 на SM-L715F з Android 17/API 37. Обидві команди завершилися Success. Збереглися `wfId-4`, усі чотири поточні параметри пульсу, усі десять записаних прив’язок у кеші провайдерів, початкові дати встановлення та дозволи геолокації. Прапорець DEBUGGABLE після оновлення відсутній. Погода потребувала описаного перемикання на інший циферблат і назад. В активному режимі перевірено календар, погоду, компас, тиск, сонячні часи, кроки, пульс та обидва заряди. Природний AOD зафіксовано окремо разом із `mWakefulness=Dozing` і `mScreenState=DOZE`. Це підтверджує цей перехід і цикл пробудження/AOD на цьому годиннику; повторні жести підняття руки, відновлення після перезавантаження та економію батареї/CPU не вимірювали.

[Перевірка приватності APK](apk-privacy.md) стосується саме опублікованих файлів.

Після міграції встановлюй оновлення з release-підписом. Старий debug-підпис не замінить release. Щоб повернути попередню поведінку коду, збери її **release-ключем** зі збереженим lineage та належним кодом версії.

## Локальна контрольна копія

До змін збережено код `014cf17` та обидва debug APK 0.2.0 з контрольними сумами й окремою копією. Git bundle дозволяє відновити попередній код. Старі APK придатні до міграції; після ротації ключа вони не є способом прямого повернення. Копія не містить відновлюваного архіву приватних системних налаштувань циферблата.
